01 / 产品理解

它解决的不是聊天，而是任务交付

天衍连接模型、知识、Skill 与本地文件，让用户通过对话组织任务，并直接获得文档、PPT、网页等可继续编辑的结果。

输入

目标与上下文

用户说明任务，并授权文件、知识与工具。

执行

模型与技能协同

系统调用模型、知识库、Skill 或 MCP 完成步骤。

输出

可编辑交付物

结果不止是回答，而是可预览、修改和复用的产物。

产品定位：企业级桌面智能体，以本地与云端能力协同完成任务。

02 / 走查与测试

把“感觉不好用”变成可跟进的问题

以首次使用、文件处理、长任务与多轮修改为核心场景进行探索式走查，记录复现路径、预期结果与实际表现，并区分体验、逻辑与模型问题。

01定义任务明确用户、输入与预期产物
02执行走查覆盖主路径与异常路径
03记录证据环境、步骤、截图与结果
04问题归因体验 / 逻辑 / 模型 / 性能
05确认优先级影响 × 频率 × 阻塞程度
06复测关闭验证修复并补充回归场景

工作记录：27 条需求与 34 条 Bug，覆盖任务执行、文件处理与交互反馈。

03 / 新手引导

让用户在第一次任务中理解产品

首次进入产品时，用户不仅不知道“能做什么”，也不知道如何选择模型、Skill 与知识。引导被设计为一条可完成的首次价值路径。

  1. 01建立认知
  2. 02选择场景
  3. 03示例启动
  4. 04获得结果
  5. 05完成新手任务
场景化

从目标出发

用写作、分析、PPT 等任务场景替代功能名词堆叠。

示例启动

降低空白页压力

预填可编辑指令，并展示将调用的知识与工具。

渐进反馈

用完成感促学习

新手任务清单与悬浮技巧按场景出现，不打断主任务。

TRY IT / 新手引导原型

第一步，不必从空白开始

选择与你的工作有关的场景，从一条示例指令开始。体验引导如何逐步交还操作主动权。

04 / 团队协作版

给 AI 执行增加上下文、责任与审核

团队任务不能让 AI 从头到尾自行运行。原型以项目为容器，将知识、成员、节点状态与人工审核纳入同一条执行链路。

体验团队协作原型 ↓
01

共享上下文

团队知识库和项目资料统一管理，AI 继承可用上下文。

02

明确责任

节点可分配给成员或 AI，并保留角色与权限边界。

03

人工接管

关键结果需要查看、修改与审核后才能流转和归档。

TRY IT / 团队协作原型

AI 执行之后，由谁确认？

以团队内容任务为例，体验节点协作、交接说明、提交审核与退回修改，查看知识如何随任务流转。

05 / 复盘

从体验观察，走向产品判断

方法

以任务而非页面为测试单元

一条完整任务链更容易暴露上下文断裂、状态不清与结果不可控的问题。

边界

区分产品问题与模型问题

先判断输入、编排、检索和交互是否可靠，再讨论模型能力与评测。

闭环

让问题能被复现和验证

记录环境、输入、预期与实际结果，并在修复后进行同场景复测。
